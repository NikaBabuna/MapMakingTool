# F-010 — Pluggable Pool compute

**Goal:** G-002  
**Status:** `done`

## Job (approved)

Make Pool update behavior a **pluggable compute strategy** wired via `EngineSetup`. Keep G-001 heartbeat/`nudge` + scripted emissions as the **default**. Custom compute can replace that logic without editing hardcoded rules inside `Pool`.

**Out of scope:** wider field carrier (F-011), pluggable emission policy beyond what compute emits (F-012), product module, world generation.

## Functional requirements (approved)

| ID | Requirement (measurable) | Status |
|----|--------------------------|--------|
| FR-1 | Callers can supply a Pool compute strategy via `EngineSetup`. | met |
| FR-2 | When none is supplied, behavior matches today's default: each update `value += 1`; if Input View has `nudge` active, also `value += 100`; then emit the existing scripted category list. | met |
| FR-3 | A custom compute can change Pool state differently (different `value` and/or declared field writes) without editing hardcoded heartbeat/`nudge` rules inside `Pool` — those rules live only in the default strategy. | met |
| FR-4 | Compute runs once per Step, sees the staged Input View, and may write into the shared event buffer (default still emits scripted paths). Step order otherwise unchanged. | met |
| FR-5 | All prior Step tests stay green (`mvnw test`). Engine still has no UI/CLI/`product` compile deps. | met |
| FR-6 | Architecture docs record the new extension point. | met |
