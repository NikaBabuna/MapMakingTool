# F-023 — Placeholder CLI + in-UI console

**Goal:** G-005  
**Status:** `done`

## Job (approved)

Add a dispatcher in `cli` (`status`, `advance [N]`, `dump`, `at X Y`, `layers`). Headless CLI keeps `--steps N` (existing tests stay). The map gets a Console control that sends lines through that same dispatcher and refreshes after `advance`. `ui` may depend on `cli` only for this. Close **G-005**. No `engine` edits, no Swing in `product`, no `JFrame` in tests.

**Out of scope:** a real command language, sockets, climate, pan/zoom, prettier tectonics.

## Command formats (approved, stored)

Placeholder verbs. Unstable. Integer tokens. Extra arguments are errors.

| Line | Success output |
|------|----------------|
| `status` | `step={n} width={w} height={h} seed={s}` |
| `advance` | same as `advance 1` |
| `advance N` | `step={n}` after `session.advance(N)` (`N >= 0`) |
| `dump` | `session.settledWorld()` |
| `at X Y` | `x={X} y={Y} elevation={e} plate={id} vx={vx} vy={vy}` |
| `layers` | `elevation` / `plates` / `plate_velocity` each on its own line |

Unknown / empty / bad tokens → `error: …` and non-zero exit when run headlessly.

`--steps N` remains a **batch flag**: DEFAULT session, advance N, print dump only (not the `advance` line). Must not change F-019 output.
