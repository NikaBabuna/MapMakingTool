# F-004 — Systems + typed merge + provenance

**Goal:** G-001  
**Status:** `done`

## Job (approved)

Add real **Systems** (replacing stub-only claimers for this path), **Sub-System** composition inside a System, and **typed merge + provenance** so claiming Systems can write into a Step output buffer and the engine applies a deterministic merge to the Pool before settle.

Loop after this Step: `update → claim → run Systems/Sub-Systems → typed merge → apply → clear buffer → settle`.

**Out of scope:** claim/finish barrier counters (F-005), full multi-run determinism Goal box (F-005), Delete Request, non-finishing Systems, Views/CLI/UI, domain Systems.

**Skeleton decisions (approved):** Systems run synchronously; Pool gains a typed field map; Delete Request omitted; conflict-resolution Sub-System hook when write-ranges overlap.

## Functional requirements (approved)

| ID | Requirement (measurable) | Status |
|----|--------------------------|--------|
| FR-1 | A **System** claims by category ancestry (same rules as F-003 claimers) and, when it claims, runs its Sub-Systems and produces **OUT_SYS** into a Step-level output buffer. | met |
| FR-2 | **System independence:** two Systems that claim the same event each see the **same Pool snapshot**; neither reads the other’s OUT_SYS in that Step. | met |
| FR-3 | A System is composed from **Sub-Systems** selected/wired by config; Sub-Systems with **disjoint** declared write-ranges may run in any order with the same OUT_SYS; **overlapping** ranges invoke a config-supplied **conflict-resolution** Sub-System that yields one deterministic order/outcome for the conflict set. | met |
| FR-4 | Step output values carry **provenance** (which System produced them). Resolvers operate on **(System, value)** pairs, not bare values. | met |
| FR-5 | **Typed merge** before apply: **Static** (deterministic pick-one), **Increment** (sum), **Constant** (writes are no-ops; Pool value kept), **Destructive** (exactly one write valid per Step; deterministic pick-one). **Delete Request** not implemented. | met |
| FR-6 | After merge, result **applies to the Pool** once; event buffer clears; no same-Step event refill (F-003 rule holds). | met |
| FR-7 | Prior Steps stay green (F-001/002/003/009); `engine` still has no UI/CLI/`product` compile deps. Stub `EventClaimer` path remains for F-003 witnesses. | met |
