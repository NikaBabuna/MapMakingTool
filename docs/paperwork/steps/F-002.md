# F-002 — Pool + Step loop + Step 0 config

**Goal:** G-001  
**Status:** `done`

## Job (approved)

Give the engine a heartbeat: a Pool that advances through discrete Steps, with Step 0 seeded only from a caller config object. Trivial deterministic state is enough. No events, Systems, merge, View, or logging facade.

## Functional requirements (approved)

| ID | Requirement (measurable) | Status |
|----|--------------------------|--------|
| FR-1 | A run can be created from a caller-supplied **config object** (no hidden global seed). | met |
| FR-2 | After creation, the run is at **Step 0** (ordinal 0) before any further advance, and Step 0’s Pool computation has used that config (ADR-005). | met |
| FR-3 | Each Step’s computation invokes Pool **`update` exactly once**. | met |
| FR-4 | The caller can advance **N** Steps (N ≥ 1); after that, the current Step ordinal is observable. **Rule:** `stepIndex()` is the 0-based index of the last completed Step. Create completes Step 0 → `stepIndex() == 0`. Each `advance()` increments by 1. After create + `advance(n)`, `stepIndex() == n`. | met |
| FR-5 | After a Step completes, tests can read a **settled** Pool snapshot (no half-applied Step exposed). | met |
| FR-6 | Same config + same N advances → **same** observable settled state (trivial determinism for this spine). | met |
| FR-7 | `engine` still has **no** compile deps on UI/CLI/`product`; F-001 and F-009 tests stay green. | met |
