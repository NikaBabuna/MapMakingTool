# F-049 — CLI as full runner

**Goal:** G-009  
**Status:** `done`

## Job (approved)

Upgrade `cli` so one process owns one `ProductSession` and can drive a full headless run: construct/configure, advance, query diag/pool/schema/systems, dump — all through `CommandDispatch`. Keep non-interactive (no stdin REPL); batch/`--steps` stay, but stop being a parallel “special world” beside the command surface.

**Out of scope:** terminal UI rebuild (F-050), runner chrome/panels (F-051+), engine production edits.

## Functional requirements (approved)

| ID | Requirement (measurable) | Status |
|----|--------------------------|--------|
| FR-1 | CLI can start a session with explicit seed (and document defaults); same session used for subsequent commands in that invocation. | met |
| FR-2 | Multi-command batch in one invocation (e.g. flags and/or repeated lines) runs on that one session via `CommandDispatch` — not a second parser. | met |
| FR-3 | `--steps N` remains; after advances, dump/query still goes through the shared command surface (or is clearly an advance+dump convenience on the same session). | met |
| FR-4 | Diag / pool / schema / systems / session verbs from F-048 work headless with success/error exit codes. | met |
| FR-5 | Docs updated (architecture “placeholder” retired for CLI runner); no F-050/F-051 claims; incremental suite green; no `engine` production edits. | met |
