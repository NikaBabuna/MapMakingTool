# F-071 — Product module organised

**Status:** `done`  
**Type:** `Cleanup`  
**Goal:** G-012

## Job

The product module's 39 files move out of one flat package into packages that follow the paper: the world area with its mechanisms and its two chapters (crust, motion), and the session area with its diagnostics. No package holds more than 12 files. Classes named with verbs get noun names, boolean queries get `is`/`has` names, and history ids leave the code comments. Every folder of the module, main and test, gets a deep-dive README and a navigation row. The world and session pages of the paper drop their code quotes and member links, gain `Code:` lines, and hand the step-to-member mapping to the new READMEs. The cli and ui modules change only their imports. Behaviour is identical.

Target layout (`com.aethelgard.product.…`), approved with the Job:

| Package | Files | Paper |
|---|---|---|
| `world` | `ProductHost`, `ProductCategories`, `GenerationTickPolicy`, `ProductGeneration` | wiring, reference |
| `world.topology` | `SphereTopology` | topology |
| `world.fields` | `Grid`, `Lockers`, `Occupancy`, `PlateRegistry`, `PlateVelocities`, `WorldFields`, `WorldSpec`, `Plates` | fields, seed |
| `world.boundaries` | `Boundaries`, `BoundaryContact`, `BoundaryKind`, `BoundaryTracing` | boundaries |
| `world.interaction` | `AreaFlux`, `BoundaryInteraction`, `MotionIntent` | interaction |
| `world.crust` | `Orogeny`, `RidgeCreation`, `MarginRelief`, `ContinentalCollision`, `Isostasy`, `CrustPrecedence`, `Subduction` | the crust chapter |
| `world.motion` | `GeometryApplication`, `VelocityIntegration`, `PlateKinematics` | the motion chapter |
| `session` | `ProductSession`, `WorldDump` | run, dump |
| `session.diagnostics` | `DiagnosticCollector`, `DiagnosticIds`, `DiagnosticsHub`, `PhaseTiming`, `RingDiagnosticCollector`, `TimingSubSystem` | diagnostics |

`Plates` sits in `fields` and `diagnostics` is its own package, to avoid package cycles. The root `package-info.java` is deleted; what it says moves into the module README, and the empty root packages become exempt layout folders.

Renames: `TraceBoundaries`→`BoundaryTracing`, `IntegrateVelocity`→`VelocityIntegration`, `ApplyGeometry`→`GeometryApplication`, `RidgeCreate`→`RidgeCreation`, `Subduct`→`Subduction`, `ContinentalCollide`→`ContinentalCollision`, `ThicknessToElevation`→`Isostasy`. Boolean members: `continental`→`isContinental`, `continentalCell`→`isContinentalCell`, `enabled`→`isEnabled`, `anyMoving`→`hasMovingPlate`, `different`→`isDifferent`, `raggedSkip`/`raggedExtra`→`isRaggedSkip`/`isRaggedExtra`; `selectsLip` keeps its name under the verb-question exception.

Tests move to the package they test: `world` (`GenerationTest`, `WorldCreationTest`), `world.topology` (`SphereTopologyTest`), `world.boundaries` (`BoundaryTest`), `world.crust` (`CrustTest`), `world.motion` (`PlateMotionTest`), `session` (`ProductSessionTest`, `WorldDumpTest`), `session.diagnostics` (`SessionDiagnosticsTest`). The 11 cli and ui files that import product types change their imports and renamed names only.

Decisions at approval: the three cycles between phase packages (`boundaries`↔`crust`, `crust`↔`interaction`, `crust`↔`motion`) stay, and the conventions page gains the rule that the phase packages of one area are peers and may call each other, while a lower layer (fields, topology) never calls up (option A, the recommendation). The type names are as listed.

Structure is checked at Verify against the blueprints: every product folder has a README that passes its Check, or is exempt; no package holds more than 12 files; the name sweep passes against the conventions; no product header carries a record id; every rewritten page passes the new Checks; every new README has a navigation row; every link resolves.
