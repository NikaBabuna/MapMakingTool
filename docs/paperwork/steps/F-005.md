# F-005 — Claim/finish + determinism witness

**Goal:** G-001  
**Status:** `done`

## Job (approved)

Make the **claim/finish barrier** real and observable, and lock a **determinism witness** so the same config + Systems + N Steps always settle to the same Pool — including when independent Systems run in different registration orders.

**Out of scope:** non-finishing Systems, Delete Request, Views/CLI/UI, System output → next-Step event emission.

**Skeleton decisions (approved):** Systems still run synchronously and always finish; claim count = Systems that claimed ≥1 event; finish count = those Systems reporting finished once; merge only when claim == finish; determinism covers re-runs and System list permutation.

## Functional requirements (approved)

| ID | Requirement (measurable) | Status |
|----|--------------------------|--------|
| FR-1 | Each Step tracks **claim count** and **finish count** for Systems. A System that claimed ≥1 event must report **finished** exactly once before merge. | met |
| FR-2 | **Barrier:** typed merge / Pool apply happens only when `claimCount == finishCount`. Counts are **observable** after the Step (tests need no async wait). | met |
| FR-3 | Stub-only claimers (no System) do not inflate claim/finish System counters; unmatched + F-003 behavior unchanged. | met |
| FR-4 | **Determinism:** same `EngineConfig` + same setup (tree, Systems, schema) + same N advances → **equal** settled Pool (`value`, `updateCount`, typed `fields`). | met |
| FR-5 | **Order independence across Systems:** two setups that differ only by **System list order**, with independent field writes, settle to the **same** Pool after the same Steps. | met |
| FR-6 | Prior Steps stay green; `engine` still has no UI/CLI/`product` compile deps. | met |
