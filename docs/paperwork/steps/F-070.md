# F-070 — Folder and code rules in the protocol

**Status:** `done`  
**Type:** `Documentation`  
**Goal:** G-012

## Job

The protocol makes good organisation automatic for any agent on any project. Every folder an agent creates gets a README and a navigation row in the same Step, with no opt-out; only six kinds of folder are exempt, and the project lists its concrete ones on its conventions page. A code folder's README becomes the deep dive into that folder, with a new blueprint that fails a README that is only a list. Code is organised one job per folder, and a folder over the conventions limit gets split. Every agent follows the conventions page and adds to it whenever it brings in something new. The architecture paper keeps concept, engineering and maths, and hands names, wiring, and "which member does this step" to the code READMEs. The Step flow and the whole-tree audit enforce all of this. The protocol still names nothing about this project.

What changes (approved with the Job):

| Where | Change |
|---|---|
| Quality rules | New rules 3.14–3.17: every folder gets a README and a navigation row, with no opt-out; one job per code folder; code follows the conventions page and keeps it current; the paper/README split. Rule 3.5 points to the right README blueprint |
| New blueprint: `doors/code-door.md` | A code README states: the folder's one job (first sentence); **Why** it's organised this way, what belongs and what doesn't; **How it works** (wiring, order, where to start reading); **Depends on / Used by**; **Where each step happens** (paper step → member → file); **Contents** (each file and subfolder: what it does, its main types or functions); and pointers to the paper page and conventions. Its Check fails a list-only README, a missing entry, an undeclared type name, or a record id |
| Docs READMEs | Every docs README gets a required **Why** part of at most three sentences. This applies to the folder README, `docs/README.md`, the architecture abstract and the level-page blueprints |
| Paper blueprints | Mechanism pages drop code excerpts, member links and the "Where it lives" table, may name a type in passing, and end with `Code:` links to the code READMEs. Level pages link the code README for their entry point. The abstract's rule for its Conventions paragraph changes to match |
| "Landmark" opt-out | Removed everywhere: `phase.md`, the Step flow, the Amendment flow, the header blueprint, the doc map |
| Step flow | A proposal must say which folder each new file goes into and which conventions row places it, list each new folder's README and navigation row, and add `conventions.md` when it brings in something uncovered. WORK creates and updates the READMEs of the folders it touches, and follows the naming and header rules |
| Whole-tree audit | Lists every folder on disk. Checks each has a README that passes its blueprint and a navigation row. Checks the folder limit, names, headers, and record ids in Purpose lines against the conventions page (code findings go to you for approval, since fixing them changes code) |
| Navigation | The doc map lists every code folder that has a README. The code route becomes paper page → code README → member. The Step flow's reading set adds the conventions rows and the touched folders' READMEs |
| Map and definitions | `map.md` gains an Article on code READMEs, and its architecture row says concept, engineering and maths. The definition of "Door" covers both kinds |
