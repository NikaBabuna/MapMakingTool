# F-072 — Engine and command line organised

**Status:** `done`  
**Type:** `Cleanup`  
**Goal:** G-012

## Job

The engine and cli modules get the treatment the product module had. Three engine packages take the paper's words (`diag`→`diagnostics`, `event`→`events`, `system`→`systems`), boolean queries read as questions, and history ids leave the code comments. Every folder of both modules, main and test, gets a deep-dive README and a navigation row; the six existing engine package READMEs, which are lists, are replaced. The engine and cli pages of the paper drop their code quotes and member links and gain `Code:` lines. Product and ui change only their imports. Behaviour is identical.

What stays, and why (approved with the Job): `Engine` and `EngineSetup` stay in `pool`, because `Engine` calls ten package-private methods of `Pool`, and moving it would force those open as public API; `pool` stays at 10 files. The cli stays one package, because the cli module is one area of the paper with 5 files, and by the conventions its own package is that area.

Renames: `Engine.eventBufferEmpty`→`isEventBufferEmpty`, `CliResult.ok`→`isOk`, `CliRunner.flagMode`→`isFlagMode`; `EventClaimer.claims` keeps its name under the verb-question exception.

Source: the three renamed packages move with `git mv`, with package lines, imports, and headers updated throughout; the 7 engine `package-info.java` files and the cli's one are deleted, their content going into the READMEs, and the engine's empty root package becomes an exempt layout folder; 33 lines of record ids leave 17 engine and cli files. The engine's `diag`, `event`, and `system` test packages move with their code; `pool`, `merge`, `user`, and the root helper `TestSystems` stay. About 15 product and ui main and test files change their imports, and `MapHost` calls `isOk`.

READMEs: `engine/README.md` and `cli/README.md` rewritten as code doors; the 6 engine main-package doors replaced; new doors for the engine's test packages — root, pool, merge, user, diagnostics, events, systems (seven folders; the proposal said six by miscount); new doors for the cli main and test packages; the engine links in 8 product doors relinked.

Decisions at approval: a package is documented by its README only, and no package keeps a `package-info.java` (the conventions page's Java File row says so; ui's one goes in F-073). The peer rule is widened: the mechanism packages of an area are peers and may call each other, and a package of values or geometry calls no package above it; this covers the engine's existing cycles `pool` ↔ `systems` and `pool` ↔ `user`, which stay.

Structure is checked at Verify against the blueprints: every engine and cli folder has a README that passes its Check, or is exempt, and a navigation row; the name sweep passes; no record ids remain; every rewritten page passes; every link resolves.
